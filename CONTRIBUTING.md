# Contributing

Thanks for helping improve pk-validate. Contributions should preserve the library's privacy-first, structural-validation scope.

## Before opening a pull request

1. Open an issue for significant API changes or new validation modules.
2. Add or update tests for every behavior change.
3. Run `npm test`, `npm run typecheck`, and `npm run build`.
4. Update the README and CHANGELOG when public behavior changes.

## Data and correctness

Do not add carrier or identity/area-code datasets without citing an authoritative, verifiable source and documenting its limitations. Never claim that a structurally valid CNIC or telephone number exists or is assigned. Do not add code that logs or transmits submitted identifiers.

## Pull requests

Keep changes focused, describe the user impact, and include test coverage. By participating, you agree to follow the Code of Conduct.
